## 当前入口

| 入口                                       | 内容与存储                                         | 教程、聊天与新闻                             |
| ------------------------------------------ | -------------------------------------------------- | -------------------------------------------- |
| 普通浏览器 `/`                             | 原内存 Demo；刷新清空                              | 自动教程关闭；不挂载主流程聊天和新闻         |
| 普通桌面                                   | 新档绑定 `minimal-test-package@1.2.0`，使用 SQLite | 自动教程关闭；不挂载主流程聊天和新闻         |
| DEV「诊断 → 主流程验证（内存，刷新清空）」 | `mainflow-short@0.1.0`，独立内存仓库               | 启用教程、聊天与新闻，可验证 schema 6 主流程 |
| DEV「诊断 → 退出主流程验证」               | 重载并返回普通入口                                 | 随入口切换恢复普通装配                       |

主流程验证也可通过 `?mainFlowPreview=1` 进入，仅在 DEV 生效。桌面开发窗口使用这条入口时同样不初始化或读写 SQLite。进入、退出和刷新会清空浏览器当前内存档案；同页退出账号再登录可以恢复该页内的进度。桌面持久存档不受这条预览路径影响。

已有存档保持自己的精确 `contentRef`，不随新档默认值重绑。普通 UI 暂不挂载主流程聊天和新闻，因此已有主流程测试档的底层状态不能用来证明普通入口已经完成接入。

装配依据：[main.tsx](../src/main.tsx)、[bootstrap.tsx](../src/app/bootstrap.tsx)、[主流程内存入口](../src/app/mainFlowPreview.ts)、[桌面默认内容](../src/content/bundledRepository.ts)、[App.tsx](../src/ui/App.tsx)。

| 配置作者链 | 固定 Luban、XLSX/结构化文本、TS 组装、来源诊断、严格加载与版本发布      | 新主流程使用 schema 6；旧作者模型保留兼容用途  |
| 主控与存档 | 主图 DAG、条件推进、池开放与派发、Core/Session 同次 CAS、save schema 5  | 正式池策略与冲突体验仍待决定                   |
| 聊天       | 独立实例、回复树、选择计数、最终结果、恢复；可拖动 CMD 式浮窗与延迟退场 | 浮层已经实现，仍由 DEV 主流程入口挂载          |
| 新闻与动作 | 发布与已读事实、最高层阅读页、关闭后提交已读并触发一次动作              | 浮层已经实现，仍由 DEV 主流程入口挂载          |
| 账号教程   | 账号首次资格、正常完成/中途退出后的队列清理与恢复                       | 普通入口暂时关闭自动教程，DEV 主流程入口可体验 |
| 本地声音   | Windows sherpa KWS 与 TTS、旁白播放及录音互斥                           | 真实设备效果、回声与干净安装验收仍需补齐记录   |
| 结局       | 旧结局选择、剧情和基础视图                                              | 演出后注销返回登录尚未接线；短流程不配置结局   |

聊天与新闻浮层的实现不等于普通入口已经启用新流程。后续正式启用需要一起核对 UI 挂载、默认内容、教程开关、旧存档和桌面持久路径。

历史 UI 验收记录属于 CMD 样式调整前的浮层版本；CMD 样式调整记录只包含静态检查，不能将前一版浏览器验收直接算作最终样式验收。详细范围见 [表现层历史记录](archive/implementation/presentation-handoff-2026-10-07.md)。

## 文档维护约定

- `product/` 维护已确认产品语义；`architecture/` 维护现行技术契约；`development/` 维护操作；`ui/` 维护表现层约定。
- 当前入口、功能接入状态与开发待办集中更新本文，其他文档通过链接引用。产品中的待决定规则仍由需求文档定义。
- 代码中的 Schema、公共接口和迁移文件是技术定义来源；文档中的类型片段用于解释契约。修改契约时同步更新调用方、测试和对应文档。
- `archive/` 保存带日期和适用范围的历史记录，停止追加“当前状态”。其中旧默认、样本数值、会话分工和测试数量不作为现行要求。
- 模块内 README 保留直接使用方法。移动文件时同步更新本地链接；语音工具 README 还由构建脚本复制进产物。
- 验证记录写明实际执行日期、命令、范围、结果和跳过原因；后续改动不能复用历史通过数量。
