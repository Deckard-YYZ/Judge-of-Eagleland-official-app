## 工具与基线

本轮使用官方 Luban v5.1.0，提交 `df34215d2e22035073d1af83d44e3ac0744dc3b3`。作者机器需 .NET 8 或兼容 SDK，游戏运行时不依赖 Luban 或 .NET。工具固定信息由仓库中的 `content-authoring/luban.lock.json` 记录，工具路径按作者环境配置。

实施前，类型检查、声音配置一致性和依赖边界检查通过。原有 64 个测试文件共 500 项测试中，首次高并发运行有两个旧用例超过五秒超时，其余 498 项通过；将这两个文件单独以两个 worker 运行后，11 项测试全部通过。该记录是实施前基线，不代替完成后的全量回归。

## 小样验收要求

- 作者链路：实际表格、双语长文和类型化配置经过 Luban 与组装，产物通过正式内容加载器。修改数值或文案能够重新生成；无效引用和缺失语言能够定位来源。
- 运行规则：两轮案件推进、判决效果、一次配置动作触发和条件派发由真实 Core 与 Session 执行；状态与派发事实在同次提交中保存，重载不重复触发。
- 展示交互：指示框从本轮选项呈现后独立加载一至两秒，选项可以不服从指示，当前轮完成后消失；ActionInput 错误影响配置状态且仍需完成。
- 兼容与失败：保留旧包与旧档语义，生成失败不破坏有效输出，保存失败不提前发布候选状态。

## 上一轮完整配置系统的实现边界

完整阶段由 GPT-6.1 Sol high worker 实现，并由独立 worker 定向审查及主代理验收。完整样本为 `configuration-complete@0.1.0`，独立于骨架、小样和原有游戏内容版本。它沿用 schema 5，包含 16 张 XLSX 工作表、3 个案件、4 个阶段、2 段聊天及 PNG/WAV 资源，覆盖人物及案件人物关联、媒体资源、阶段条件、聊天局部分支和对话外行为分支。阶段数量和转移关系由配置定义，没有固定三个阶段或线性顺序。

公开流程查询入口为 `src/application/configurationQueries.ts`。入口校验内容、游戏状态及调用方提供的 `FlowFacts`，Game Core 执行无副作用的有限规则计算。事实包含当前阶段、此前聊天节点和当前激活聊天节点；本轮没有将这些流程事实自动写入 Session 或存档。这是旧实验契约：`chatLastNode` 不等于新需求中的已发布最终结果，`externalBranches` 让案件事件直接走聊天局部分支，聊天节点或外部 event 的 `unlockCases/unlockChats/enterStage` 也不是新主控剧情图的执行方式。

| 配置能力             | 实际实现与消费边界                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 人物及人物关联       | 作者表编译至既有 `case.characters`；公开查询返回人物与可选头像资源引用                                                    |
| 图片、音频等资源     | 资源表声明路径；构建工具读取真实二进制，正式加载器校验文件清单，发布和复导逐字节比较                                      |
| 阶段推进             | `queryStageTransitions` 解释条件与目标资格；唯一匹配、冲突、无匹配及无后继分别返回明确结果，不保存阶段                    |
| 聊天出现             | `queryChatAvailability` 计算开启资格，不自动弹出界面                                                                      |
| 已有聊天节点         | `queryChatNode` 基于显式激活节点返回回复或终止节点后果；开启条件变化不封锁已经开始的聊天                                  |
| 搁置聊天后的隐藏推进 | `queryChatExternalEvent` 要求真实案件事件记录，并匹配当前节点的配置分支；多分支匹配返回待决，不规定与玩家回复的竞争优先级 |
| 聊天关联内容         | `queryFlowEvent` 及节点查询返回解锁案件、聊天、进入阶段的意图；不会据此自动派发全部内容或更改存档                         |
| 生成门禁             | `content:check-all` 顺序真实导出注册的三个作者包，核对生成模型及完整运行包；缺少工具配置明确失败                          |

公开查询与 Game Core 的内部 `compute*` 分开命名；外部调用不应绕过公开入口的校验。阶段查询的 `terminal` 仅表示该阶段没有后继，不表示游戏结局。重复消费查询结果、提交流程事实与内容派发的原子性，需在未来业务接入时落实。

独立审查补齐了旧模型的两处问题：初稿没有明确绑定案件事件的聊天隐藏分支；聊天开启条件被误当成持续交互门禁。修正后，玩家搁置聊天、完成判决导致条件变化，仍可基于原激活节点继续回复或匹配隐藏分支。引用、局部图、本地化覆盖、原型键与交互专用状态隔离均纳入校验。该回归保留为旧包能力的历史证据，不能作为新聊天生命周期的验收。

现有结局演出仍沿用旧队列机制：最终选择先产生配置 hook 和派发事实，再锁定结局；结局剧情排在此前已入队的 hook 后面。新增回归约束动作错误不得改变已经锁定的结局，但不代表“触发结局时如何处置未完成交互”的产品流程已改造完成。这项现存流程差距留待结局业务开发处理。

Windows 生成 CI 已配置 Node 24、.NET 8 及锁定的官方 Luban 提交，执行真实复导、测试和静态检查；本地通过不等于已经运行过 GitHub 工作流。
