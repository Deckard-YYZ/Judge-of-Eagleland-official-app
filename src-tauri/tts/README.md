# Fixed local narration assets

- Runtime: existing `sherpa-onnx =1.13.8` shared Windows x64 CPU DLLs from `artifacts/voice/native/lib`. This TTS preparation never downloads/replaces DLLs.
- Model: `vits-melo-tts-zh_en`, fixed `system` voice, speaker 0, speed 1.0, two CPU threads; `zh-CN` and `en-US`. The archive README identifies one female Chinese/English speaker.
- Archive and member SHA-256 are checked in `scripts/tts-assets.json` and `model-manifest.json`; no hashes are regenerated by preparation. Developer preparation downloads only the pinned archive. Application execution is offline.
- Selected resources total 177,481,452 bytes: model.onnx, tokens.txt, lexicon.txt, date.fst, number.fst, phone.fst, LICENSE, README.md. The additional int8 model, heteronym rules and dictionary directory are not used by this configuration.
- Resource hashes are checked on first model creation, before entering native code. One cached model is reused; subsequent disk changes are checked after process restart.

From the repository root, run `python -X utf8 scripts/prepare-tts.py`, then `cargo run --locked --manifest-path src-tauri/Cargo.toml -- --tts-model-smoke`. The smoke generates fixed public fixture WAVs and `tts-smoke.json` next to the development executable. It does not open output devices, microphones, game state, or saves. Basic synthesis and cancellation evidence is retained in `smoke-evidence.json`; audio stays in ignored build output.

The IPC accepts only requestId, text, zh-CN/en-US, system, and optional diagnostic operationId. Limits: 500 Unicode scalars, 30 seconds of mono finite float32 PCM with absolute amplitude <=1, actual sample rate 8000–48000 Hz, one native task/model, 60-second cooperative generation deadline. Cancellation invalidates results immediately; BUSY remains until native work actually exits. The sherpa callback executes between generated batches, so neither timeout nor cancellation preempts a running ONNX call. Output bounds are checked again before IPC; short bounded input also limits work within a single batch. No background queue or disk audio cache exists.

## Scope of verification

The five fixtures cover tutorial order and intro in both languages, plus a warm Chinese repeat. All English fixture words exist in the pinned lexicon. Real synthesis with the deployed existing DLL succeeded at 44100 Hz, with nonempty finite PCM. Cancellation during real generation returned CANCELLED, rejected overlap, and allowed a subsequent synthesis. Rust tests also cover missing/corrupt assets, NUL/path-like voice IDs, input/audio bounds, and deadline classification.

Synthesis evidence is not listening evidence. Human pronunciation/timbre review, loudspeaker/headphone and room-tail testing, WebView output devices, clean installer/offline installation and redistribution approval remain outstanding. Archive LICENSE contains the MyShell.ai 2024 MIT notice and is preserved in deployment; it does not by itself establish a completed review of every model/pronunciation asset. No cloud/system-voice fallback, SDK upgrade, extra speakers, streaming or phoneme alignment was introduced.

Sources: [official model guide](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/vits.html#vits-melo-tts-zh-en-chinese-english-1-speaker), [model source repository](https://github.com/myshell-ai/MeloTTS), and the locally installed 1.13.8 Rust crate `src/tts.rs` used for API validation.
